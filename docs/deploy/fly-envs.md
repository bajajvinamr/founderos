# FounderOS Fly.io Environment Variables Reference

Complete reference of environment variables for single-tenant Fly.io deployments.

## Overview

Environment variables fall into three categories:
1. **Required** — must be set for the app to boot
2. **Strongly Recommended** — highly recommended for production deployments
3. **Optional** — features disabled if not set, graceful degradation

The `fly-provision.sh` script handles most of this automatically. This document is a reference for manual configuration or troubleshooting.

---

## Required Secrets

These are set via `fly secrets set` and never appear in `fly.toml`.

### `DATABASE_URL`

**Type:** Secret (required)  
**Format:** `postgres://user:password@host:port/database`  
**Source:** Fly Managed Postgres, Supabase, Neon, or self-hosted Postgres  
**Notes:**
- Must be a valid Postgres connection string
- The app will fail to start without it
- Migrations run automatically on boot

**Example (Supabase):**
```
postgres://postgres:secretpassword@db.example.supabase.co:5432/postgres
```

**Example (Fly Managed Postgres):**
```
postgres://founderos:generatedpassword@internal.founderos-db.internal:5432/postgres
```

### `FOUNDEROS_SECRETS_MASTER_KEY`

**Type:** Secret (required)  
**Format:** Base64-encoded 32-byte random value  
**Source:** Generated during provisioning; preserve across deploys  
**Notes:**
- DO NOT regenerate after initial deployment — all encrypted secrets depend on it
- If lost, you cannot recover encrypted data
- `openssl rand -base64 32` generates a suitable value

**Auto-generated by:** `fly-provision.sh`

## Strongly Recommended Secrets

Set these via `fly secrets set` for production deployments.

### Authentication: Better Auth

| Variable | Type | Required? | Notes |
|----------|------|-----------|-------|
| `BETTER_AUTH_SECRET` | Secret | Strongly recommended | 32-byte random value. `openssl rand -base64 32`. Session signing key. |
| `BETTER_AUTH_URL` | Secret | Yes (if auth enabled) | Public base URL: `https://founderos-<slug>.fly.dev`. Used for OAuth callbacks. |
| `BETTER_AUTH_TRUSTED_ORIGINS` | Secret | Optional | Comma-separated list of allowed OAuth origins. Auto-set to `https://founderos-<slug>.fly.dev` if omitted. |

**Example:**
```bash
fly secrets set BETTER_AUTH_SECRET="$(openssl rand -base64 32)" --app founderos-acme
fly secrets set BETTER_AUTH_URL="https://founderos-acme.fly.dev" --app founderos-acme
```

### AI/LLM Providers

| Variable | Type | Required? | Default | Notes |
|----------|------|-----------|---------|-------|
| `ANTHROPIC_API_KEY` | Secret | If using Claude | None | Enables Claude adapters. Format: `sk-ant-...` |
| `OPENAI_API_KEY` | Secret | If using OpenAI | None | Enables OpenAI adapters. Format: `sk-...` |
| `GEMINI_API_KEY` | Secret | If using Gemini | None | Enables Google Gemini. |
| `ANTHROPIC_BEDROCK_BASE_URL` | Secret | Optional | None | AWS Bedrock endpoint for Anthropic models. |
| `CLAUDE_CODE_USE_BEDROCK` | Env | Optional | `false` | Set to `true` to use Bedrock instead of Anthropic API. |

**Example:**
```bash
fly secrets set ANTHROPIC_API_KEY="sk-ant-..." --app founderos-acme
```

### Email & Notifications

| Variable | Type | Required? | Default | Notes |
|----------|------|-----------|---------|-------|
| `RESEND_API_KEY` | Secret | If sending email | None | Resend email service API key. |
| `EMAIL_FROM` | Env | If sending email | None | Sender email address (e.g., `noreply@founderos.com`). |
| `SENTRY_DSN` | Secret | Optional | None | Sentry error tracking. If set, exceptions are reported. |

**Example:**
```bash
fly secrets set RESEND_API_KEY="re_..." --app founderos-acme
fly config set EMAIL_FROM="noreply@founderos.io" --app founderos-acme
```

### Clerk Auth (if replacing Better Auth)

| Variable | Type | Required? | Notes |
|----------|------|-----------|-------|
| `CLERK_SECRET_KEY` | Secret | If using Clerk | Usually `sk_live_...` |
| `CLERK_PUBLISHABLE_KEY` | Secret | If using Clerk | Usually `pk_live_...` |

## Public Environment Variables

These are set in `fly.toml` `[env]` section or via `fly config set`. They appear in the running process and are not secret.

### Server

| Variable | Type | Default | Notes |
|----------|------|---------|-------|
| `PORT` | Env | `3100` | Port the server listens on. Fly HTTP service forwards to this. |
| `HOST` | Env | `0.0.0.0` | Bind address. Keep as `0.0.0.0` for Fly. |
| `NODE_ENV` | Env | `production` | Keep as `production` in Fly. Controls logging verbosity. |

### FounderOS Deployment Config

| Variable | Type | Default | Notes |
|----------|------|---------|-------|
| `FOUNDEROS_HOME` | Env | `/founderos` | Root of persistent volume. Instance config, secrets, workspace data stored here. |
| `FOUNDEROS_INSTANCE_ID` | Env | `default` | Single-tenant deployments use `default`. Multi-tenant would use `tenant-<id>`. |
| `FOUNDEROS_DEPLOYMENT_MODE` | Env | `authenticated` | Options: `authenticated` (login required), `public` (no auth). |
| `FOUNDEROS_DEPLOYMENT_EXPOSURE` | Env | `private` | Options: `private` (internal), `public` (internet-facing). |
| `SERVE_UI` | Env | `true` | Serve the web UI from the same server. Set to `false` if UI is on a separate domain. |

**Example for public, authenticated deployment:**
```toml
[env]
  FOUNDEROS_DEPLOYMENT_MODE = "authenticated"
  FOUNDEROS_DEPLOYMENT_EXPOSURE = "public"
  FOUNDEROS_DEPLOYMENT_HOME = "/founderos"
  SERVE_UI = "true"
```

### URLs & Hostnames

| Variable | Type | Required? | Default | Notes |
|----------|------|-----------|---------|-------|
| `FOUNDEROS_PUBLIC_URL` | Env | If `DEPLOYMENT_EXPOSURE=public` | Inferred from Fly URL | Public URL: `https://founderos-<slug>.fly.dev` |
| `FOUNDEROS_ALLOWED_HOSTNAMES` | Env | If `DEPLOYMENT_EXPOSURE=public` | Inferred from Fly URL | Comma-separated allowed hostnames. Used for request validation. |
| `FOUNDEROS_API_URL` | Env | Optional | Inferred | Base URL for API calls from the UI. Only set if UI is on a different domain. |

**Example:**
```toml
[env]
  FOUNDEROS_PUBLIC_URL = "https://founderos-acme.fly.dev"
  FOUNDEROS_ALLOWED_HOSTNAMES = "founderos-acme.fly.dev"
```

## Optional Features

### Telemetry & Observability

| Variable | Type | Default | Notes |
|----------|------|---------|-------|
| `SENTRY_DSN` | Secret | None | Sentry error tracking DSN. If set, exceptions and errors are reported. |
| `FOUNDEROS_TELEMETRY_ENABLED` | Env | `true` | Enable FounderOS telemetry (usage, errors). Set to `false` to disable. |

### Storage & Attachments

| Variable | Type | Default | Notes |
|----------|------|---------|-------|
| `FOUNDEROS_ATTACHMENT_MAX_BYTES` | Env | `52428800` (50 MB) | Max file upload size in bytes. |
| `FOUNDEROS_ALLOWED_ATTACHMENT_TYPES` | Env | `image/*,application/pdf,text/*,application/json` | MIME types allowed for upload. |

### Database & Backups

| Variable | Type | Default | Notes |
|----------|------|---------|-------|
| `FOUNDEROS_DB_BACKUP_ENABLED` | Env | `false` | Enable automatic DB backups to local filesystem. |
| `FOUNDEROS_DB_BACKUP_INTERVAL_MINUTES` | Env | `60` | Backup frequency (minutes). Only if backups enabled. |
| `FOUNDEROS_DB_BACKUP_RETENTION_DAYS` | Env | `7` | Keep backups for N days. Older backups are deleted. |
| `FOUNDEROS_DB_BACKUP_DIR` | Env | `${FOUNDEROS_HOME}/db-backups` | Where to store backup files. Should be on persistent volume. |

### Development & Debugging

| Variable | Type | Default | Notes |
|----------|------|---------|-------|
| `DEBUG` | Env | Unset | Set to `founderos:*` or specific module to enable debug logging. |
| `FOUNDEROS_CONTEXT` | Env | `prod` | Set to `dev` for verbose logging and lenient error handling. |

## Setting Secrets & Public Env Vars

### During Provisioning

`fly-provision.sh` handles the most common setup:

```bash
# Basic
./scripts/fly-provision.sh acme-corp --db-url "postgres://..."

# With optional API keys (picked from environment)
export ANTHROPIC_API_KEY="sk-ant-..."
export BETTER_AUTH_SECRET="$(openssl rand -base64 32)"
./scripts/fly-provision.sh acme-corp --db-url "postgres://..."
```

### After Provisioning: Secrets

Use `fly secrets set` to add or update a secret:

```bash
fly secrets set ANTHROPIC_API_KEY="sk-ant-..." --app founderos-acme
```

List current secrets (names only, not values):

```bash
fly secrets list --app founderos-acme
```

### After Provisioning: Public Env Vars

Edit `fly.toml` and update the `[env]` section, then redeploy:

```bash
# Edit fly.toml
# [env]
#   FOUNDEROS_DEPLOYMENT_EXPOSURE = "public"

fly deploy --app founderos-acme
```

Or set via flyctl (but `fly.toml` is source of truth):

```bash
fly config set FOUNDEROS_DEPLOYMENT_EXPOSURE=public --app founderos-acme
```

## Validation & Health Checks

### Verify Configuration

After deploy, check that required envs are set:

```bash
fly config show --app founderos-acme
fly secrets list --app founderos-acme
```

### Health Endpoints

The server exposes three health check endpoints — these are auto-checked by Fly and accessible manually:

| Endpoint | Purpose | Details |
|----------|---------|---------|
| `GET /api/healthz` | Liveness | Returns 200 if process is alive. No DB call. |
| `GET /api/readyz` | Readiness | Returns 200 if process is alive AND DB is accessible AND auth is bootstrapped. |
| `GET /api/health` | Status JSON | Returns detailed status: versions, adapters, provider availability, etc. |

**Example checks:**

```bash
# Quick liveness check
curl https://founderos-acme.fly.dev/api/healthz

# Full readiness check
curl https://founderos-acme.fly.dev/api/readyz

# Detailed status
curl https://founderos-acme.fly.dev/api/health | jq .
```

## Troubleshooting

### "DATABASE_URL not set" at boot

The app requires `DATABASE_URL` as a secret. Verify it's set:

```bash
fly secrets list --app founderos-acme | grep DATABASE_URL
```

If missing, set it:

```bash
fly secrets set DATABASE_URL="postgres://..." --app founderos-acme
fly deploy --app founderos-acme
```

### "FOUNDEROS_SECRETS_MASTER_KEY not set or invalid"

The encryption key is required and must be valid base64. If you lost it, all encrypted data is unrecoverable. Create a new one:

```bash
fly secrets set FOUNDEROS_SECRETS_MASTER_KEY="$(openssl rand -base64 32)" --app founderos-acme
```

⚠️ This will invalidate any previously encrypted data (e.g., stored API keys).

### App starts but readiness check fails

Check logs for database or auth bootstrap errors:

```bash
fly logs --app founderos-acme --follow
curl https://founderos-acme.fly.dev/api/readyz -v  # See the detailed error
```

### Specific provider (Claude, OpenAI, etc.) not available

Verify the API key is set as a secret:

```bash
fly secrets list --app founderos-acme | grep ANTHROPIC_API_KEY
```

Then check the provider status:

```bash
curl https://founderos-acme.fly.dev/api/health | jq '.providers'
```

## Summary: Quick Reference

**Minimal provisioning (auth only):**
```bash
./scripts/fly-provision.sh mycompany --db-url "postgres://..."
```

**Full production setup (with Claude + email):**
```bash
export ANTHROPIC_API_KEY="sk-ant-..."
export BETTER_AUTH_SECRET="$(openssl rand -base64 32)"
export RESEND_API_KEY="re_..."
./scripts/fly-provision.sh mycompany --db-url "postgres://..."
```

Then set email sender in `fly.toml` or after deploy:
```bash
# In fly.toml [env]
EMAIL_FROM = "noreply@mycompany.com"
fly deploy --app founderos-mycompany
```
